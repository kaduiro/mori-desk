## 未完了と次の順序

1. Chrome の Gmail リンクで、対象アカウントだけが未ログインの状態を隔離 Chrome プロフィールで試す。今回は両アカウントが既存 Chrome にログイン済み。B を前面にした後の A 指定の合成 URL は `/mail/u/0/` へ解決したが、Gmail の画面読み込みが完了せず、メール本文やプロフィール一致の合格根拠にはしない。ログイン順逆転も未試験。
2. Calendar の実予定で説明文と会議参加 URL の両方を HUD で開く。接続済み Calendar の当日共有予定3件には説明文と予定ページ URL があったが、会議参加 URL はなかった。予定本文や URL はこの記録に転記しない。
3. OS ログイン起動、PC 再起動、上書き更新、アンインストールとデータ保持を現在ユーザー環境または隔離 Windows で試す。2026-11-07 の読み取り専用確認では、Windows の Mori 固有の起動登録は旧開発版 `.runtime` の Electron と `bootstrap` を指していた。インストール版の画面で「未確認」となる原因は、旧実行ファイルを安全のため別登録として拒む現行ポリシーだった。修正ソースは明示的な修復ボタンと厳密な旧登録検証を追加したが、インストール版バイナリへの反映とログイン実機試験は別途確認する。
4. 別 Windows ユーザーまたは VM で空プロファイルの初回導入を試す。Docker の Linux コンテナーは Windows GUI インストールの代わりにならない。

この試験を、Mac、Chrome Web Store、Google Cloud の実効枠・課金・OAuth 公開審査、法人先行試験の合格として扱わない。

## 旧開発版のログイン登録に対する修正候補

2026-11-07 にソースを修正し、旧開発版の固定 Run 登録のコマンド、実行ファイル、Mori 専用 bootstrap、OS の有効状態が一致する場合だけブラウザー連携画面に「インストール版に修復」を出すようにした。修復はボタン操作を受けた時だけ実行し、異なるコマンド、別アプリの登録、OS 側で無効な登録、読めない登録は上書きしない。登録先をインストール版へ変更した後は読み直して成功を判断する。

再構築後のソース検査は `source_check_passes (source_matches)`。全体回帰試験は903件合格、失敗0件、スキップ1件、TODO1件。最後の設定ロック確認を追加した後は関係する28件を再実行して全件合格した。Windows x64 Setup 候補の SHA-256 は `6ACD5505C2D6B53A01B430E183A720B1DD0E444F6F103AC20C95C723C06C198D`、未署名。

利用者が承認した同じ候補を「現在のユーザーのみ」で既存のインストール先に上書きし、Setup の完了画面を確認した。インストール済み `app.asar` と候補の `app.asar` は SHA-256 `4BC5B139644E8BA7BC1BEF56339190D2543B689D94F9AA80414C27ECE7C9A917` で一致し、インストール版の本体プロセスが起動した。起動直後、Windows の固定起動登録は旧開発版を指したままで、ブラウザー連携画面に「ログイン時の自動起動：旧開発版を指しています」と「インストール版に修復」が表示された。修復ボタンを押すと画面は「有効」になり、固定 Run 登録を読み直すと `C:\Users\akkun\AppData\Local\Programs\Mori Desk\Mori Desk.exe --mori-startup=login` を指していた。OS ログイン後の実起動はまだ未確認。

## Gmail の未ログイン試験手順

既存の Chrome プロフィールや既存ログインは削除しない。A の Chrome プロフィールは既にあるため、重複作成は求めない。[Chrome 公式のゲストモード手順](https://support.google.com/chrome/answer/6130773)に沿い、右上のプロフィール画像から「ゲスト プロフィールを開く」を選ぶ。ゲストの窓では `115akkun@gmail.com` のみ Gmail にログインし、大学アカウントは追加しない。パスワードと二段階認証は利用者自身が入力する。ゲストの窓を閉じるとその窓の Cookie は消える。

1. ゲストの Gmail 右上から、現在ログインしているアカウントが A のみであることを確認する。B が見えたら試験条件が成立していないため、その状態で合否を付けない。
2. Mori Desk を B に連携し、B の実在メールの詳細にある URL をコピーする。メールの件名・本文・完全な URL は試験記録へ転記しない。
3. A のみのゲスト窓で新しいタブを開き、コピーした B の URL を貼り付ける。B のログイン要求が出るか、A の受信箱・A の別メールへ誤遷移するかを確認する。後者なら安全性試験は不合格とする。
4. Mori の「Gmail で開く」ボタンも別に押し、Windows がどの Chrome プロフィールを開いたかと対象アカウントを確認する。A のみのゲスト窓で開かなければ、手順3の結果をこのボタンの合格根拠にしない。
5. 試験後は Mori の連携を A に戻す。ゲスト窓を閉じると試験用のログイン状態は消える。

ログイン順を逆にした試験は、閉じ直した新しいゲスト窓で B を先に、A を後に追加して行う。既存プロフィールのログイン順は変えない。

2026-11-07 の読み取り専用 Calendar 確認では、接続先から見える10カレンダーの当日予定は0件だった。この日の実予定による説明文・会議 URL の HUD 試験は実施できない。合成テストの結果を実予定の受入に読み替えない。
