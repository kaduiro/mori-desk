# Calendar・Gmail HUD の操作性実装記録

2026-11-04。個人検証用の Mori Desk ソースに以下を実装した。

- キャラクターとトレイのメニューに「受信メール」を追加し、既存の Mail HUD 起動処理へ接続。
- 両 HUD を初期 400×480、最小 320×300 のサイズ変更可能な窓にし、タスクバーに表示。位置・サイズ・文字倍率・前面固定を `layout.json` v2 に保存。旧 v1 の位置を移行し、画面の作業領域に収める。
- 文字倍率 100/125/150% と前面固定の切替を追加。既定倍率は 125%。開いたメールの送信者・件名は折り返す。
- 自動配置時は他方の HUD の領域を避ける。手動で置いた窓は自動移動しない。
- 手動起動はフォーカスし、最小化済みなら復元。自動表示はフォーカスを奪わない。DND 等で閉じた自動 HUD は抑制解除後に再表示し、明示的に閉じた窓は再表示しない。Mail HUD を閉じたときの本文破棄を維持。

ソースは `patches/mori.patch` と `overlay/`。生成 `.runtime/` は最終ソースとして編集しない。複数 Gmail アカウントは [設計案](calendar-mail-ux-and-account-roadmap-ja.md)どおり、今回は単一連携・単一 HUD のままにした。

## 検証と残件

- Node 24.21.0、`npm run rebuild` 成功。前回の再構築失敗時は既存ランタイムを保持。再構築後の次回起動ソース検査は `source_check_passes (source_matches)`。
- `npm test` は 896 件中 894 件成功、失敗 0 件、環境条件によるスキップ 1 件、TODO 1 件。終了コード 0。新設テストは旧位置設定の移行、重なり回避、作業領域への補正、Mail のサイズ・文字倍率・前面固定の保存、IPC 入力検証、抑制解除と明示的閉鎖を確認。
- Windows 実機では両 HUD の表示、予定・未読件数、文字倍率と前面固定欄、キャラクターの右クリックメニューの「受信メール」を確認。外部ブラウザーが前面を占めたため、枠のドラッグ、文字倍率切替、タスクバー復帰、右クリックメニュー項目のクリック後の再表示は引き続き操作受入が必要。位置・サイズ・倍率・明示的閉鎖・抑制解除は Node の動作テストで確認。
- Calendar の実予定詳細・会議 URL・OS ログイン起動、Gmail の正しいアカウントが Chrome で未ログインのときのリンク動作は未完了。利用対象は Chrome に限定し、別ブラウザーの合否は求めない。
- 本番 Cloud プロジェクトは未作成。組織の利用枠・課金・OAuth 管理者承認、法人先行試験、配布用ビルド・署名は組織の準備後に検証する。個人用 OAuth 設定とローカル認証情報は配布しない。
