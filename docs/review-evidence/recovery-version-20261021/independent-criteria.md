## 1. 判定の意味

各項目をPASS / FAIL / UNKNOWN / NOT-RUNで記録する。該当差分が存在しない項目は「今回未実装」と明記し、実装済みと同じ扱いにしない。診断が正しく「未確認」を伝えることは差分安全性のPASSになり得るが、観測復旧のPASSにはならない。

今回の限定した差分レビューが合格しても、J2（正の統合動作）、J3（Windows限定試用）、J4（社員配布）を自動的に合格へ進めない。候補と証拠を正しく対応付けられたことも、帰属の正しさや業務成立を証明しない。

## 2. 最小診断の独立期待値

診断用の外部真値は、次の5つの層を別々に故障させて作る。製品の`healthy`、`accepted`、表示文字列を正解に使用しない。

1. 本体/bridgeへの通信・認証・永続化。
2. 拡張workerの起動・登録・通常の再試行。
3. 対象ページobserverの存在・有効世代・新しい報告。
4. 表示中の会話と中央本文/生成操作の帰属。
5. サイト権限・対象タブの状態・利用者の明示停止。

| ID | 外から与える条件・反例 | 必要な結果 |
|---|---|---|
| D01 | 本体接続/認証は成功、observerから新観測なし、bindingは未確認 | 本体通信の成功だけでページ監視成功と表示・集計しない。確認中の層を残す |
| D02 | 本体停止、認証拒否、storage読込/書込失敗、タブ照会失敗を別条件にする | 異なる障害を同じ「保存失敗」や一律「接続済み」に丸めない。特定不能は未特定とする |
| D03 | workerが応答しない、workerは動くがページへ到達しない、ページは応答するが帰属不明 | 検知できた事実と推定を分離する。通信断だけで自然worker停止と断定しない |
| D04 | 権限なし、利用者停止、凍結/破棄、未対応画面を別条件にする | 許可を超えた再起動・読取をしない。原因の根拠がなければ分類を確定しない |

| D06 | 診断読取り前後を比較し、手動health/retryが修復を誘発する | 受動snapshotと能動検査を区別する。能動操作は介入として明示し、その後の成功で無介入復旧の失敗を上書きしない |

## 4. 実画面の帰属根拠なしで有効化してはいけないこと

次の項目は今回の診断・照合が完成しても許可しない。別の帰属根拠と独立レビューが必要である。

- URL一致、時間経過、DOM静止、ノード置換、sidebar選択、root属性だけの切替、接続済み、artifact一致を理由としたprovider自動承認。
- 本番bindingを合成の「confirmed」へ置換する、force/health/診断から帰属gateを迂回する、未確認の属性や内部APIを導入すること。
- 未帰属の抜粋、running、terminal、新規通知、focus成功/ACKを採用すること。
- root/name/URLだけB、中央の本文/生成操作はAの反例を正常なBとして扱うこと。A→B→A、戻る/進む、同URLの文書交代、旧ノード複製、session履歴なしも未確認を維持する。
- 以前runningで復帰時idleという事実から、観測空白中の終了を補完すること。
- 一方provider、通常前面タブ、空欄固定、全てunknownという限定結果から、ChatGPT/Claude両方の復旧完了を宣言すること。

解消にはprovider・画面・言語・確認日時・対象版・中央本文と生成操作の対応・更新順がずれる反例・失効条件が必要である。実環境未接続はUNKNOWNのまま残す。

## 6. 後続差分の検証方法

この文書のhashを親へ送信した後にだけ、今回の差分と必要なowner module/公開protocolを読む。テスト期待値は本書から作り、製品関数・既存fixtureをoracleへ流用しない。APIの接続方式を学ぶことと、期待値の生成を分離する。

小さな独立driverで、手動定義の状態/版/ファイル集合と故障点を与え、返却schema・UIの意味・副作用を照合する。必要なら`/tmp`の隔離コピーで実行し、共有runtimeへ書き込まない。低影響の表示差分について実装をなぞるだけのテストは増やさない。

検出力を確認する場合は、(a)同版異byteを常に一致とする、(b)本体connectedだけでページhealthyとする、(c)disk上の新版を旧実行コンテキストの版として報告する、(d)未知カテゴリをそのまま出力する、から該当する最小故障を選ぶ。原版PASS→意図したassertionのFAILが必要であり、構文エラーや起動不能は検出力と数えない。

最終記録は、実際に確認した差分/ファイルhash、独立基準hash、操作・入出力・介入の有無、試行範囲、実行環境、各項目の判定、未解消事項、業務完成との違いを含める。期待値は実行後に変更しない。仕様解釈を改める必要が生じた場合はv1を残して理由付き追補を別ファイルへ書く。
