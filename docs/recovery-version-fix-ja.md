# 接続競合・更新時の版照合の追加修正

記録日: 2026-10-21（Asia/Tokyo）。本体 `0.1.3-preview.1` / 拡張 `0.1.7` の開発候補。

## 判定

接続の非同期処理が停止・置換をまたぐ競合と、ソース更新後に古い本体を起動できる問題を修正した。
実サービスの会話所属確認は未実装のままであり、**ページ監視の完成、限定試用、社員向け配布は未達**。
今回の通信試験やディスク検査から、実 Chrome / ChatGPT / Claude の復旧成功を推定しない。

## 変更した動作

| 対象 | 再現した問題 | 修正後 |
|---|---|---|
| 接続の認証・資格保存 | 保存や暗号処理を待つ間に停止・切断・接続置換が起きても、古い継続処理が接続済み通知、通信、heartbeat を開始できた | 非同期処理の後に接続の所有権・世代・有効状態を確認し、失効した処理を終了する |
| 接続状態通知の callback | 接続済み通知の中で停止しても、その後の ready 通知と heartbeat が始まった | callback の後にも所有権を確認し、接続 Promise が未決着のまま残らないように終了する |
| ペアリングの競合 | 古い pair の finally が新しい pair の排他状態を解除し、余分な resume 接続を始められた | 現在の pair の所有者だけが排他状態を解除する |
| 起動前のソース照合 | 構築時の入力記録が存在しても起動時に比較しておらず、同じ版番号の古い本体を起動できた | 上流の固定値・パッチ・overlay の入力と構築記録を比較し、overlay のコピーも実際の byte 列で確認する |
| 読取り専用の版診断 | ソース・構築済み本体・別の拡張フォルダーの違いをまとめて確認する手段がなかった | `npm run doctor` / `check-windows.bat` で版・対象ファイル・不一致を表示し、実行中 Chrome は未確認と明示する |
| 診断の異常ファイル | 初期実装の manifest 読取りが FIFO 等で停止した | 通常ファイル・リンク・開いた descriptor を確認してから読み、不正なファイルを検査不能として扱う |
| 設定画面の説明 | 新しいページ観測を保留する候補なのに、通常利用できる説明が残っていた | 冒頭で監視が未完成であること、再接続・F5 で有効にならないことを表示する |

callback 内の停止と pair の並列操作は、transport API の境界で再現した反例である。
通常の worker の callback は状態更新だけを行い、設定画面からの pair はキューで直列化される。
この二つを、利用者の定期的な切断の原因と断定しない。元の切断がどの層で起きたかは未特定。

## 版診断の使い方と範囲

Windows では `check-windows.bat` を実行する。既に用意された Node を使い、ダウンロードや修復は行わない。
Node が PATH にある場合は次を使える。

```sh
npm run doctor
npm run doctor -- --json
npm run doctor -- --extension-dir /path/to/browser-bridge
```

一致は終了コード `0`、不一致または検査不能は `2`、実行・引数エラーは `1`。
実行中の Chrome については `chrome://extensions` の対象拡張の版と読み込み元を別途照合する。
`diskChecksPassed` は、ソースに含まれる対象ファイルとローカルの構築物の照合結果である。
余分なファイル、継承コード全体、依存ライブラリ全体、実行中本体、実行中 Chrome、
provider の観測、自動復旧の成功を証明しない。

起動時に `MORI_RUNTIME_SOURCE_MISMATCH` が表示された場合は、本体を終了して
`setup-windows.bat` または `npm run setup` で再構築する。拒否のために既存 runtime・設定・データを削除しない。
版番号が同じでもソース入力やコピーされたファイルの内容が異なれば不一致になる。
Git がない場合や、別の Git リポジトリの下に ZIP を展開した場合は、親の commit を自分の版として表示しない。

## 検証記録

証拠は [recovery-version-20261021](review-evidence/recovery-version-20261021/) に保存する。
最終集計は同ディレクトリの `validation-summary.json` に、対象ファイルの hash とともに記録する。

全体回帰は **328 tests / 327 PASS / 0 FAIL / 1 TODO**、exit `0`。
その後に公開候補 CLI の差分パス処理を修正し、影響する専用 9 件を再実行して全件 PASS を確認した。
製品・起動前照合・doctor の byte は全体実行から変更していない。9 件は全体件数に重複加算しない。
TODO は実 provider の帰属根拠を要する `I-B8` であり、完了扱いにしない。

- 起動前照合の固定試験を旧 `d3aef35` へ適用すると、正常系 1 件 PASS / 不整合系 3 件 FAIL。
  不整合を拒否する例外が出ないことを検出した。同じ条件が修正後は通過する。
- transport の初回再現は 3 FAIL / 1 PASS。独立レビューで追加した二つの反例は 2 FAIL。
  修正後の transport 回帰は 13 PASS / 0 FAIL / 0 TODO / 0 skip。
- 独立担当は差分や既存 fixture を読む前に基準を固定し、独自の socket・暗号処理のラッチと
  ファイル構成で期待する副作用を検査した。transport は 12 件、起動前照合・doctor は 33 件を確認した。
  実装担当のテスト件数と合算して受入の充足を主張しない。
- 再構築した runtime と overlay 70 ファイルが一致した。拡張の比較対象 18 ファイルも一致した。
  実ディスクの `doctor` は exit `0` だが、実行中 Chrome / 本体 / provider / 自動復旧は `NOT_CHECKED`。

検査環境は Linux / Node `24.19.0`。Windows の BAT 実行、実 Chrome のページ監視、
実サービスでの会話切替・背景利用・自然 worker 停止・45 秒以内の復旧は今回確認していない。
以前の合成 Chrome 試験の `FAIL-no-recovery` と、実 provider の未達 `I-B8` は解消した扱いにしない。

## 続けて必要な確認

実際の ChatGPT / Claude で、中央の本文と生成操作部が現在の会話に属する根拠を確認する。
URL、sidebar の選択、経過時間、root の会話 ID だけで所属を推測しない。
根拠を独立評価して実装できた後に、正しい新規観測・通知・移動先と無介入復旧を確認する。
単一タブの非表示の過去会話を同時観測する機能や、会話全文を AI で要約する機能は今回追加していない。

Windows の実機受入、候補そのものの Windows CI、対象 Mac の実機確認、配布経路の確認は別の判定として残す。
機械試験の件数や差分の安全性を、業務全体の完成保証へ読み替えない。
