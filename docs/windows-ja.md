# Windows でのセットアップと実験

このリポジトリは **Mori Desk の開発プレビュー**です。固定した
clawd-on-desk のソースに Mori の変更を適用し、オリジナルのキャラクターと
ブラウザ連携を試すための構成です。

実際の ChatGPT / Claude の画面での DOM 判定、Windows / Mac の GUI、
署名済みインストーラーの動作は、社員へ配布する前に実機で確認してください。
ローカルの自動テストが通っても、それらが確認されたことにはなりません。

## 1. 開発用 PC の準備

Windows の通常のデスクトップ環境で実行します。最初は Windows x64 と
Chrome を対象にします。Electron のウィンドウ確認には Windows 側の
PowerShell または BAT を使ってください。

最初に次を各公式インストーラーから入れてください。

- [Git for Windows](https://git-scm.com/install/windows)
- [Google Chrome](https://www.google.com/chrome/)

**Node.js は初回 BAT が必要に応じて自動で準備します。** 手動インストールは必須ではありません。
既存の安定版 Node.js **24.18.0 以降の 24.x** と隣接する npm があれば使い、なければ
公式の Node.js **24.22.0** の ZIP をダウンロードし、固定 SHA-256 と照合してから
プロジェクト内の `.tools/node-v24.22.0-win-x64`（ARM64 PC は `win-arm64`）へ配置します。
既存の別バージョンの Node.js は削除しません。

Git のインストール後は PowerShell を開き直して確認できます。

```powershell
git --version
```

専用 Node の準備では、管理者権限、PC 全体の PATH 変更、PowerShell の実行ポリシー変更は
行いません。BAT 内の PowerShell コマンドは公式ファイルの取得・ハッシュ検証・展開に使います。
Git / Chrome の自動インストールは含みません。会社の PC では社内の配布手順を使ってください。

Node.js を PC 全体で使う場合は [公式インストーラー](https://nodejs.org/en/download/archive/v24.22.0)
を使う方法もあります。専用 Node だけを準備した状態では、普通の PowerShell で
`node --version` や `npm.cmd` が見つからなくても、Mori Desk の BAT は専用 Node を使用できます。

## 2. Mori Desk を入手する

```powershell
git clone https://github.com/kaduiro/mori-desk.git
cd mori-desk
```

GitHub の Code → Download ZIP から入手して展開する方法でも構いません。
この場合も、固定 upstream を取得するセットアップ処理には Git が必要です。
ZIP は右クリック → **「すべて展開」**し、`setup-windows.bat` と `overlay` が並ぶ
フォルダーを開いてください。ZIP の中から BAT を直接実行しないでください。

### Node.js だけを先に準備する

`install-node-windows.bat` をダブルクリックします。Git は不要です。
成功すると使用する Node.js と npm を表示します。その後、同じフォルダーの
`setup-windows.bat` で Mori Desk 本体をセットアップしてください。

## 3. 初回は setup-windows.bat

`setup-windows.bat` をダブルクリックします。Node がなければ先に自動で準備し、
成功すると、そのままブラウザ用モードの Mori Desk を起動します。
Node/npm を PC 全体の PATH へ導入済みの開発環境で、コマンドで同じ作業を行う場合は：

```powershell
npm.cmd run setup
npm.cmd start
```

初回セットアップでは次の処理を実行します。

1. `upstream.lock.json` に記載した repository と commit を確認します。
2. upstream を `.upstream/clawd-on-desk` に取得し、固定 commit の Git blob を
   読み出します。キャッシュ内の未追跡ファイルやローカルの書き換えはコピーしません。
3. upstream の artwork / themes / Git metadata を除外して専用 staging を作ります。
4. `patches/mori.patch` と `overlay/` を適用します。
5. Node のコードから Mori の SVG、PNG、ICO を生成します。
6. staging 内で `npm ci` を実行し、Electron と生成素材を確認します。
7. すべて成功した後に `.runtime` を切り替えます。

処理中はアプリの dependencies をダウンロードするため、ネット接続と空き容量が
必要です。既存の `.runtime` がある場合、途中で失敗した staging に置き換えません。
生成ディレクトリの所有権が確認できなければ、削除や置き換えを止めます。

## 4. ブラウザ拡張機能を一度読み込む

Chrome で `chrome://extensions` を開き、開発者モードを有効にして
「パッケージ化されていない拡張機能を読み込む」を選びます。

選ぶ場所は、`setup-windows.bat` と同じ場所から **`overlay` → `extensions` → `browser-bridge`**
と進んだフォルダーです。`manifest.json` が直接入っていることを通常のエクスプローラーで
確認し、Chrome では `browser-bridge` フォルダー自体を選んでください。
Chrome のフォルダー選択画面ではファイル名が表示されない場合があります。

起動中の Mori Desk のキャラクターを右クリックし、**「ブラウザ連携・セッション」**を開きます。
**「接続コードを作成」→「コードをコピー」**を押し、Chrome 側の
**「MORI Browser Bridge（プレビュー）」**の設定画面へ貼り付けて **「接続する」**を押します。
設定画面は初回追加時、または Chrome の拡張機能アイコンを押すと開きます。コードは 2 分で失効します。

「拡張機能のフォルダー」は Mori Desk のブラウザ連携画面にあるボタンです。
そのボタンからは、セットアップ成功後のコピー `.runtime/extensions/browser-bridge` を開きます。
最初からある `overlay` 側を読み込む手順なら、このボタンを使う必要はありません。

既に開いていた ChatGPT / Claude のタブは、拡張機能の初回読み込み後に
再読み込みしてください。最初は通常のテキスト会話で試します。

開発者モードの拡張読み込みは技術検証用の方法です。社員向けの恒久配布では、
組織管理の拡張機能配布または組織が所有する配布経路を別途用意します。
デスクトップの BAT / EXE だけで Chrome の任意の拡張機能や権限を無断で
登録する仕組みにはしていません。

## 5. 2 回目からの起動

`start-windows.bat` をダブルクリックします。Node/npm を PC の PATH に導入済みなら、
次のコマンドでも起動できます。

```powershell
npm.cmd start
```

通常の起動では upstream の再取得、パッチの再適用、`npm ci` は行いません。
検証済みの `.runtime` をそのまま起動します。
専用 Node があれば各 BAT が毎回その場所を選ぶため、PC を再起動しても手動の PATH 設定は不要です。
通常の起動では Node のダウンロードもしません。Node が不足する場合は
`install-node-windows.bat` または `setup-windows.bat` で準備し直します。

Mori のソースを更新したときは、Mori Desk を終了してから
`setup-windows.bat` を再実行してください。拡張機能に変更があれば
`chrome://extensions` で再読み込みし、対象の AI タブも再読み込みします。

## 6. CLI も使う実験

**元の Clawd on Desk と、通常モードで起動中の Mori Desk を終了してから**
`start-cli-windows.bat` を使います。

```powershell
npm.cmd run start:cli
```

このプレビューでは元の Clawd の設定を自動移行しません。同じ OS ユーザーで
二つのアプリに CLI hooks / runtime を同時管理させないでください。
必要な CLI 連携は Mori の設定画面で明示的に有効にします。
権限承認などの追加機能も、必要な範囲を確認して設定画面から有効にしてください。

ブラウザ専用の実験に CLI モードは不要です。

このプレビューでは CLI からのアプリ自動起動を無効にしています。先に専用 BAT で
Mori を起動してください。OS ログイン時の起動を設定した場合もブラウザ用モードに
なるため、CLI を使う場合は起動中の Mori を終了して専用 BAT から起動し直します。

## 7. Windows の EXE インストーラーを作る

Windows でセットアップが成功したら、`build-windows.bat` または次を実行します。

```powershell
npm.cmd run build:win:x64
```

生成先：

```text
.runtime/dist/Mori-Desk-Setup-0.1.2-preview.1-x64.exe
```

ビルドスクリプトは GitHub Release へ自動公開しません。この段階の unsigned
preview を、署名済み・社員向けの完成版と扱わないでください。Windows の署名や
社内配布方法は、実機テスト後に整備します。

ビルド済み Electron アプリはランタイムを同梱するため、将来の社員向け
インストーラーでは社員に Node / Git を用意してもらう必要はありません。
拡張機能の導入と初回ペアリングは別の工程として残ります。

Mac 用の `.app` / `.dmg` は Mac の CI runner で作れます。署名・公証と
社員の Mac でのウィンドウ、最前面表示、スリープ復帰、タブへの移動の確認が
必要です。Windows の結果だけで Mac の動作確認済みとはしません。

## 8. 自動テストと実機チェック

以下は Node/npm が PC の PATH にある開発環境向けです。

```powershell
npm.cmd run verify:electron
npm.cmd test
```

テスト対象は `.runtime/test/browser-*.test.js` と `mori-*.test.js` です。
Windows でも shell glob に頼らず、実在するファイルを列挙して実行します。

実機では少なくとも次を確認します。

- 一つのタブで生成開始 → 生成終了 → HUD の通知 → 元のタブへ戻る。
- 複数タブで、一方の生成が終わっても他方の実行中表示が残る。
- 生成の中断、エラー、観測できなくなった状態を「正常終了」と誤表示しない。
- HUD を押しても対象タブを開けなかった場合、未読を失わない。
- Chrome / Mori の再起動、スリープ復帰、タブの再読み込み。
- 会社の Windows / Mac で、表示倍率と複数ディスプレイを変えても操作できる。

## 9. うまくいかないとき

### Node のバージョンが合わない

`install-node-windows.bat` を実行してください。対応しない既存 Node を削除せず、
Mori 専用の Node を準備できます。以降は Mori の BAT から起動します。
PC 全体の Node を使う開発者は、Node 24.18.0 以降の 24.x と npm を導入し、
端末を開き直してください。

### Node のダウンロードやハッシュ検証に失敗した

公式 `https://nodejs.org/dist/` への接続と、黒い画面のエラーを確認してください。
ダウンロードした ZIP の SHA-256 が固定値と違う場合、展開・実行を止めます。
通信が直った後に同じ BAT を再実行してください。証明書検証や社内ポリシーを無効化する
必要はありません。Node の準備が失敗しても既存 `.runtime` は変更しません。

### .tools に不完全な同名 Node フォルダーがある

不完全なフォルダーを自動上書きする処理はありません。エラーに表示された場所を確認し、
必要なファイルを保管してから別名へ移し、`install-node-windows.bat` を再実行してください。
出所や内容が不明なフォルダーを削除する必要はありません。

### npm.ps1 の実行ポリシーエラー

上の手順どおり `npm.cmd` を使用してください。BAT 内の処理は Node から
npm の JavaScript CLI を直接起動し、PowerShell の実行ポリシー変更は行いません。

### ダウンロード・dependency の準備に失敗した

エラーの repository URL / npm / Electron のメッセージを確認します。
社内 proxy・証明書・ネットワークに制約がある場合は社内の設定を使います。
証明書検証を無効にする設定は不要です。通信が直ったらセットアップを再実行します。

### 所有権エラー

`.runtime` / `.upstream` が別のプロジェクトからコピーされた、別の場所へ
移動された、または marker がない場合は自動上書きを止めます。
既存データを保管し、新しい空のフォルダーに Mori の repository を取得して
セットアップし直す方法が確実です。個人の CLI 設定を削除する必要はありません。

### .mori-setup-lock が残った

セットアップ中に端末や PC が終了すると lock が残ることがあります。
別の Mori セットアップが動いていないことを確認してから、プロジェクト直下の
`.mori-setup-lock` だけを取り除いて再実行します。不明なプロセスを一括終了したり、
ユーザーの `.claude` / `.codex` / `.clawd` を削除したりしないでください。

### HUD は表示されたが AI の状態が出ない

まず Mori Desk と拡張機能の両方を更新します。Mori Desk の右クリックメニューから
**「終了」**してから、このリポジトリのフォルダーで次を実行してください。

```powershell
git pull --ff-only
.\setup-windows.bat
```

Git で取得していない場合は、最新版 ZIP を別の空フォルダーに展開してセットアップします。
既存フォルダーに上書き展開する必要はありません。Chrome が参照する拡張機能のフォルダーも
新しい `overlay/extensions/browser-bridge` を選び直してください。

1. Chrome の `chrome://extensions` で **「MORI Browser Bridge（プレビュー）」**を探し、
   カードの再読み込みボタンを押します。バージョンが **0.1.4** になったことを確認します。
2. AI を利用している同じ Chrome プロファイルで、拡張機能のアイコンを押します。
   **「接続済み」**か確認し、未登録なら Mori の接続コードを登録します。
3. 既に開いている ChatGPT / Claude のタブも再読み込みします。長い回答を生成中なら、
   その回答が終わってから再読み込みし、次の質問で試してください。
4. 拡張機能の **「表示されない原因を確認」**を押します。未接続・監視停止・対象タブがない・
   再読み込みが必要・画面を認識できない場合を、この画面で確認できます。
5. Mori のキャラクターを右クリックして **「ブラウザ連携・セッション」**を開きます。
   ここに行が出るのに HUD に出ない場合は、設定 → セッションで HUD を有効にし、
   常時表示のピンを確認します。キャラクターを隠す・ミニモード・自動非表示などの表示設定も確認します。

| 表示・結果 | 確認すること |
|---|---|
| 「Chrome 未登録」／HUD の「Chrome と接続」 | Chrome の拡張機能に Mori の接続コードを登録する |
| 「Chrome 未接続」 | 同じ Chrome プロファイルの拡張機能で、監視の再開・再接続を確認する |
| 「生成状態は未受信」 | 接続自体は成立。拡張機能の診断ボタンでタブと画面の状態を確認する |
| タブの再読み込みが必要 | 拡張機能の初回追加・更新後に AI のタブを再読み込みする |
| 対象タブがない | 拡張機能と同じ Chrome プロファイルで ChatGPT / Claude を開く。デスクトップ版 AI アプリはこの拡張機能の観測対象にならない |
| 画面を認識できない | 実サービスの画面変更や特殊モードの可能性がある。まず通常のテキスト会話で試す |
| 診断では生成中だが Mori の一覧に行がない | 0.1.4 の「観測を受け付けた／受け付けられなかった／未確認」の件数と理由を確認。受け付け済みなら接続状態と未送信件数を確認 |

拡張機能 0.1.0 は ChatGPT の `/g/…/c/…` 形式を対象外としていました。
0.1.1 はこの形式を通常のテキスト会話として観測しますが、プロジェクトや GPT 固有の
全機能を検証したものではありません。画面の差で状態が認識できない場合は adapter の追加修正が必要です。

0.1.3 は、従来の入力欄や回答欄の目印がない ChatGPT の別形式にも検知を追加しました。
一つの編集可能な入力欄、`Stop` / `停止` / `停止する` のいずれかの停止ボタン、
`aria-busy="true"` の処理中表示が揃うと生成を観測します。その後、入力欄が残り、
停止ボタンと処理中表示が両方消えた状態が続くと「回答を確認」と知らせます。
更新後は別々の Chrome タブで質問し、各タブの行が増えること、生成中から回答を確認へ
変わることを試してください。古い会話を開いただけでは新しい行・終了通知は作りません。
同じフォルダーから読み込んでいる拡張機能は、削除・再インポートせず再読み込みできます。

`Clawd state server listening on 127.0.0.1:23334` は、ローカルサーバーがそのポートで
待ち受けを開始したログです。Chrome のペアリング完了や DOM 観測成功を意味しません。
23334 は許可された候補の一つであり、固定で23333に変更する必要はありません。
接続コードには実際の待ち受けポートが入ります。

回答文・入力文・社内文書は不要です。不具合の切り分けには、Mori と拡張機能の
バージョン、接続状態、診断の件数、サービス名・画面種別だけを記録してください。

### 行は出るが状態が不明・タブへ戻れない・内容を区別できない

本体 `0.1.2-preview.1` と拡張機能 `0.1.4` に更新したら、キャラクター下の行にある
**「詳細」**を押します。ブラウザ連携画面の該当セッションが選択され、状態の説明と
対処方法が表示されます。移動できない行を押した場合も、この詳細へ進めます。

| 表示 | 意味と次の操作 |
|---|---|
| ブラウザ未接続 | この行を通知していた拡張機能との接続がない。Mori と Chrome の起動、拡張機能の接続状態を確認する |
| 再起動前のセッション | 現在接続している Chrome とは別の起動時の記録。現在の AI タブを再読み込みして新しい行を確認する。古い行の通知は勝手に消さない |
| タブの状態を再取得中 | 再接続やページ切り替えの後、新しい状態を受信していない。AI タブを表示し、更新されなければ再読み込みする |
| タブの状態更新が停止 | 同じブラウザとの接続はあるが、90秒を超えてこのタブの新しい状態がない。タブを表示し、拡張機能の診断で受付結果を確認する |
| この画面には未対応 | 生成状態を判定できない。同じページであることを確認できれば「タブへ戻る」で回答を確認できる |
| タブを閉じました | 保存した記録。閉じたタブへ移動はできない。必要ならブラウザの履歴から会話を開く |

詳細には、最後に観測した状態、生成開始の観測時刻、最後に状態を確認できた時刻、
ブラウザとの最終通信、未確認件数などを表示します。**ブラウザとの通信が続いていることと、
タブの生成状態が更新されていることは別**です。切断中に残った「最後に観測した状態」を
現在も生成中だという証拠にはしません。

「ChatGPT 1」だけでは区別しにくい場合は、**「この PC だけの表示名」**に
「議事録の整理」などを入力し、**「表示名を保存」**を押してください。HUD にも反映されます。
80 UTF-16 コード単位以内（一般的な日本語文字は80文字、絵文字などは2単位の場合あり）です。
空欄で保存すると自動名に戻ります。表示名はそのセッション記録に保存し、Chrome の別起動で
できた新しい行へは自動転記しません。会話本文・ページタイトルの自動取得や、内容の自動要約はしません。

「詳細」を開くことや表示名の保存で、未確認通知を確認済みにはしません。
「タブへ戻る」はページの一致を前後に確認し、成功時だけ操作開始時の通知を確認済みにします。
移動中に新しい通知が届いた場合、その新しい通知は残ります。

それでも状態が更新されない場合は、拡張機能の **「表示されない原因を確認」**を押してください。
0.1.4 では `old_document` などで観測が拒否されたことも件数と対処方法で表示します。
「生成中を画面で検知した」と「拡張機能が観測を受け付けた」と「Mori に届いた」は別の段階です。
診断は拡張機能の受付までを確認し、Mori への到達はこの詳細画面で確認します。

更新時の `git pull --ff-only` が失敗した場合は、そのままセットアップを続けないでください。
以前作成した `mori-latest-…` が `origin/main` を追跡している場合は、そのブランチで更新できます。
ローカルで分岐した古い `main` へ戻す必要はありません。

### 拡張機能に CONNECTION_REFUSED・404・context invalidated が出る

Chrome の「エラー」画面は過去の記録も残します。記録があることだけでは、現在も切断中かは
分かりません。拡張機能の設定画面にある現在の「接続済み」表示を先に確認してください。

| エラー | 意味 |
|---|---|
| `ERR_CONNECTION_REFUSED` | その試行時、表示されたローカルポートへの接続が受理されなかった。本体の現在の起動・待受けを確認する |
| WebSocket handshake の `Unexpected response code: 404` | HTTP の応答者はいたが `/browser/v1` の WebSocket 接続は成立していない。応答した製品はこれだけでは特定できない |
| `Extension context invalidated` | 拡張機能の更新・再読み込み等で、既に開いていたページの古い監視処理が拡張機能を利用できなくなった |

再接続は保存済みポートを先に試し、続いて23333〜23337を調べます。そのため、本体が
起動していない間やポートが移動した際に、複数ポートの接続エラーが記録されることがあります。
0.1.2 は自動再接続の待機中に DOM 観測やアラームが余分な探索を始めないようにします。
接続が拒否されたこと自体は隠しません。「今すぐ再接続」は待機を解除して試行します。

1. Mori の「ブラウザ連携・セッション」を開き、現在のポートと接続エラーを確認します。
   本体が終了している場合は `start-windows.bat` で起動します。起動用の黒い画面も残しておきます。
2. ソースを更新した場合は、本体を右クリック →「終了」してから `setup-windows.bat` を
   実行してください。`git pull` と `start-windows.bat` だけでは古い `.runtime` は更新されません。
3. 拡張機能を再読み込みし、回答の生成終了後に AI の会話タブも再読み込みします。
   0.1.2 は古い監視処理を停止しますが、新しい監視処理を会話タブに読み込む操作は必要です。
4. 拡張機能の「今すぐ再接続」を押し、「接続済み」になったことを確認します。
   未登録ではない限り、接続コードを入れ直す必要はありません。
5. 必要なエラー記録を保存した後、「エラー」画面の「すべて削除」で履歴を消し、
   新しい通常の質問を送ります。再び同じエラーが出るかと、現在の接続状態を確認します。

まだ接続できない場合、次の PowerShell コマンドは待受けポートを読むだけです。

```powershell
Get-NetTCPConnection -State Listen -LocalPort 23333,23334,23335,23336,23337 -ErrorAction SilentlyContinue |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

表示された行、Mori の接続画面、今回起動した際のコンソール末尾を照合します。接続コード、
鍵ファイル、会話本文は不要です。通常の HTTP GET は Mori でも404になる仕様なので、
ブラウザで `http://127.0.0.1:ポート/browser/v1` を開く方法では正常性を判定できません。

### 設定を開くと system conflict と表示される

旧版の `Saved, but currently not active due to system conflict` は、グローバル
ショートカットを OS に登録できなかったときの通知です。起動時の失敗も設定を開いた際に
同じ文面で表示しており、設定の保存やダッシュボード自体が壊れたように見える問題がありました。

`Clawd: failed to register shortcut togglePet: CommandOrControl+Shift+Alt+C` が
出ている場合は、Windows の **Ctrl + Shift + Alt + C** の登録が失敗しています。
他アプリの利用や OS の制約が考えられますが、このログだけで相手のアプリは特定できません。

0.1.1-preview.1 は対象の操作・キーを表示し、保存後だけのエラーと誤認しない文面に変更します。
新規の既定キーは **Ctrl + Shift + Alt + M** です。既に保存したキーは勝手に変更しないため、
競合が残る場合は **設定 → ショートカット → ペット表示の切替**の行で
**「デフォルトに戻す」**を押すと、明示的に M の組み合わせへ変更できます。
それも使えない場合は **「変更」**で別のキーを登録するか、**「クリア」**でこのショートカットだけを
解除してください。登録に失敗したショートカットが使えなくても、ブラウザの状態受信とは別の問題です。

`npm warn deprecated`、`npm audit` の脆弱性件数、npm の更新案内は、このキー登録の
エラーとは別です。今回の症状への対処として `npm audit fix --force` を実行する必要はありません。
