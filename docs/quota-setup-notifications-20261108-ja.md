# 個人利用向けの枠表示・接続・通知（2026-11-08）

## 実装した動作

- Gmail HUD は、この端末が予約した Gmail API units と端末内の24時間・1分の上限、各期間の残量を一覧の上に常時表示する。値は HUD の状態更新時に端末の台帳から再計算する。Calendar HUD は、この端末の直近24時間の取得回数と端末内上限を表示する。これらは Google Cloud 側の実効枠・残量ではない。
- 「個人 Google Cloud の準備」画面から Cloud の割り当てと API ダッシュボードを開ける。利用者が同じプロジェクト・同じ期間の使用量と上限を転記した場合だけ、残り目安と記録時刻を表示する。アプリは Cloud 管理権限を要求せず、値の真偽を検証しない。未入力は未確認のまま扱う。
- Chrome 拡張は、ブラウザ連携画面から同梱フォルダーを開いて Chrome で読み込む。Chrome のデベロッパーモード、拡張機能の読み込み、接続コードの入力は利用者の明示操作とする。
- CLI 連携はブラウザ連携画面のボタンから `--enable-cli` 付きで再起動できる。再起動後、既存の Agent 設定から Codex CLI と Claude Code を個別に Install する。今回の再起動操作はログイン時自動起動の引数まで変更しない。
- Gmail の優先送信者メールは、新規取得分だけ件名と本文を含まない OS 通知を出す。初回の既存メール一覧を一斉通知しない。送信者アドレスの一致は送信者認証ではない。
- Calendar は予定の `reminders` と CalendarList の `defaultReminders` のうち `popup` を読み、該当時刻に件名を含まない OS 通知を出す。HUD からその予定の通知を10分延期または端末内で解除できる。Google 側の設定は変更しない。
- 両通知は初期状態オフで、HUD の起動時表示とは独立する。通知オンで HUD を隠した場合はバックグラウンド同期を続ける。共通の通知停止時間は初期値22:00～08:00で変更できる。通知済み履歴は内容を含まないハッシュと時刻だけを端末に保存する。

## 運用上の境界

- Cloud の使用量は Console 転記時点の観測値であり、リアルタイムの残量ではない。枠は API・利用者・時間窓ごとに複数あるため、同じ期間の値だけを比較する。
- Calendar の今回の通知対象は当日取得した時刻付き予定で、終日予定、前日などに通知時刻がある翌日以降の予定、Google Tasks は対象外。Google Calendar のメール方式リマインダーも対象外。
- 通知の実表示とクリック時の前面動作は Windows/macOS の実機と OS 設定に依存する。署名のない macOS アプリの通知や Chrome 拡張の配布方法は別途実機確認が必要。
- Google OAuth の Desktop クライアント作成・同意、Chrome 拡張の読み込み、Codex/Claude の Install は利用者の明示操作を要する。アプリはブラウザーのポリシーや OS の信頼確認を迂回しない。

## 試験項目

1. Cloud 値を未入力・同期間入力・不正値で保存し、表示と旧記録の読み込みを確認する。
2. Gmail 優先送信者の既存分は通知せず、新規分だけ一度通知すること、本文や件名が OS 通知に出ないことを確認する。
3. Google のイベント個別通知とカレンダー既定通知、延期・解除、通知停止時間、再起動後の重複抑止を確認する。
4. HUD の起動時表示をオフ、通知をオンにした状態で再起動し、HUD を表示せず同期・通知することを確認する。
5. 実機で CLI 再起動、Codex/Claude 個別 Install、Chrome での拡張読み込みとペアリング、Windows OS 通知の表示を確認する。
