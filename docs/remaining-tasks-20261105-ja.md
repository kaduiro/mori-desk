# Mori Desk の残存タスク

更新: 2026-11-05（Asia/Tokyo）。この文書は PR #6、#7、#9、#10、#11 のソース変更を取り込んだ後の受入と配布作業を整理する。PR のマージは法人向け配布の完了を意味しない。

| 優先 | 作業 | 完了条件 |
| --- | --- | --- |
| P0 | Calendar・Mail HUD の Windows 操作受入 | 両 HUD のドラッグ、サイズ変更、文字倍率、タスクバーからの復帰、重なり回避、明示的な閉鎖と DND 等の抑制解除を実際の Windows 画面で確認する。再起動と OS ログイン起動でも設定と表示状態を確認する。 |
| P0 | Calendar の実予定受入 | 本人と共有カレンダーの当日予定、時間、説明、会議参加 URL、出所と詳細開閉を確認する。日付切替、オフライン、手動更新時の上限停止も実機で確かめる。予定本文と URL を検証記録へ転記しない。 |
| P0 | Gmail リンクのアカウント境界 | 対象アカウントが Chrome で未ログイン、ログイン順が逆、他のアカウントだけがログイン済みの条件で、別アカウントのメールを開かないことを確認する。誤遷移する条件では深いリンクを社内配布しない。 |
| P0 | ブラウザー監視の実環境受入 | インストール済み Chrome と現行 ChatGPT・Claude の DOM で、画面遷移、再接続、タブ競合、停止・完了・不確実状態、未読の保持を確認する。合成テストと計測キットの成功を実環境の合格に読み替えない。 |
| P1 | 組織所有の Google Cloud・Workspace 設定 | 管理者が対象30人の組織部門、Calendar と Gmail の API・Desktop OAuth クライアント、必要スコープ、Internal の適用、アクセス制御、実効利用枠、課金・予算通知を確定する。個人検証用設定を流用しない。 |
| P1 | 法人先行試験と配布判定 | 1～2人の法人アカウントで連携・再起動・予定と未読の同期・失効時の回復を試す。使用量と 403/429 を観察し、署名済み実ビルドのインストール・更新・削除・OS 信頼を確認してから30人へ配る。 |
| P2 | macOS 向け配布 | 配布対象に含める場合、macOS 実機の画面・ログイン起動、署名・公証、インストール・更新を別途受け入れる。 |
| 将来 | 複数 Gmail アカウント | 利用需要が確定した時点で、アカウント別の認証・保存・IPC・URL 境界と旧形式からの移行を設計・レビューする。現在の Mail HUD は単一連携。 |
