# Mori Desk 0.1.8 開発プレビュー

対象: Mori Desk 本体 `0.1.3-preview.1` / Chrome 拡張機能 `0.1.8`。

## この版で確認できることと制限

この更新は、ソースの版と実際に起動する版の確認、起動入口、待受の再試行、接続・同期の状態表示を反映する開発プレビューです。

**ChatGPT / Claude の新しい生成状態は監視しません。** 実サービスの画面がどの会話に属しているかを確かめる処理が未実装のため、新しいページ観測を受け付けません。次の動作は、この版では利用できません。

- 新しい会話・生成に応じたセッション行の追加。
- 新しい「生成中」「回答を確認」の表示や通知。
- 現在の観測許可を必要とする、HUD から会話タブへの移動。

通信接続の確認、サービス別の確認できない理由の表示、保存済み通知の同期は別の処理です。保存済みの行や通知が表示されても、現在の生成を観測したという意味にはなりません。F5、再接続、再ペアリングでは未実装の会話識別を有効にできません。

`0.1.4` で動いていた新しい生成監視を使い続けるための更新ではありません。利用者の指示に基づいてソースを統合する開発用の版であり、社員配布や実サービスを通した受入の完了を示すものではありません。

## 変更した処理

| 項目 | 動作 |
|---|---|
| 共通の起動入口 | `bootstrap` で現在のソース、組み立て済み本体、固定 Electron、起動結果を確認する |
| 古い本体の起動防止 | ソースと `.runtime` が不一致なら再セットアップを案内する。同じ版番号だけで一致と判断しない |
| ログイン起動 | Windows の登録内容・所有・読み戻しを確認する。状態照会だけで OS 側の無効化を戻さない |
| 待受の自動復帰 | 許可した localhost ポートを再試行し、古い待受や終了後の処理が接続情報を復活させない |
| 状態表示 | 通信、サービス別の確認状況、保存済み通知の同期、自動起動登録を区別する |
| 拡張の状態通知 | 対応する本体へカテゴリと件数だけを送る。URL・タイトル・本文・鍵を含めず、古い情報を現在の観測にしない |
| ソースフォルダーからの拡張読み込み | 生成 build 情報がなくても設定・認証を初期化する。build ID は不明のまま扱う |

HMAC 相互認証、Origin / Host の照合、保護された鍵保存、通知を永続化した後の ACK、会話・文書の照合を保持します。会話識別の制限を解除して観測を通す変更は含みません。

## Windows で更新する

更新する順序は **本体 → 拡張機能 → 既存の AI タブ**です。詳細なコマンドは [Windows 手順書 5.3](windows-ja.md#53-018-への更新手順)にあります。

1. Mori Desk のメニューから終了する。
2. Mori のフォルダーで `git pull --ff-only` を実行し、失敗したら停止する。
3. `setup-windows.bat` を実行して本体を再構築する。
4. 成功後に `chrome://extensions` で既存の MORI Browser Bridge を再読み込みし、`0.1.8` を確認する。
5. 回答生成が終わり、入力途中の文章を確認してから AI タブを再読み込みする。
6. 通信接続、会話識別が未実装という理由、保存済み通知の同期を確認する。

同じ拡張フォルダーを使っている場合は、拡張機能の削除・再インポートは不要です。Git で更新される `overlay/extensions/browser-bridge` と、セットアップで作られる `.runtime/extensions/browser-bridge` は別々です。`overlay` 側に生成 build ID がない場合は不明と表示し、本体と同じ build だとは扱いません。

バージョンを PowerShell で確認するときは `Get-Content -Raw -Encoding UTF8` を使用します。[文字化けを避けた確認コマンド](windows-ja.md#51-更新したのに版が変わらない場合)も用意しています。これは読み取りだけであり、ファイルを書き換えません。

## 検証範囲

2026-10-22 に公開候補の Git tree を隔離したディレクトリへ展開し、通常の `node scripts/setup.js` から再構築して検証しました。

| 検証 | 結果 |
|---|---|
| Linux / Node.js 24.19.0 の回帰 | 実サブテスト389件、387 PASS、0 FAIL、0 cancelled、1 SKIP、1 TODO |
| overlay の再構築一致 | 91ファイルすべてが一致。生成 build 情報2件もディスク診断に合格 |
| 継承 main / server の再構築 | 実装候補とSHA256が一致 |
| ソースフォルダーからの拡張起動 | 生成メタデータなし、生成メタデータあり、必須モジュール欠落の3ケースを確認 |
| Windows CI | 公開コミットに対する実行結果とrun URLを [PR #5](https://github.com/kaduiro/mori-desk/pull/5) に記録 |

SKIP はWindows固有のdrive/directory alias、TODOは実サービスの会話所属確認を必要とするI-B8です。成功件数に含めていません。ソースフォルダー起動の3ケースは387 PASSの内数です。

構築した本体は `0.1.3-preview.1`、拡張は `0.1.8`、build IDは `848761f391aff96d08fe76274283c9c3479d100e4a5c15b53f7918064a5fd93f` です。

新旧本体と拡張の四通りの通信試験に固定した旧版は、コミット `c56d1593676d4ff5b53996afac1e1c12da0a8e3d` の `0.1.7` です。利用者が使用していた `0.1.4` との全組合せを確認したという意味ではありません。本体の再構築を先に行ってから拡張を再読み込みしてください。

Windows の native UI smoke は実 Electron main、HUD、パネルと合成のローカル接続を確認する試験です。実際の ChatGPT / Claude の画面、Chrome 拡張のページ観測、ログイン・PC 再起動による全経路の自動復帰、署名済みインストーラー、macOS での受入は別の確認です。

未完了の実サービス確認を、自動テストの成功や build ID の一致で置き換えません。ブラウザ監視を通常利用できる版へ進めるには、実画面の会話識別根拠を確かめ、観測の受理と正しいタブ移動を実装・検証する必要があります。
